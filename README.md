# homeroom-tools

小学校の担任業務を効率化するための道具置き場。
Google Workspace for Education と Chromebook での運用を前提にしている。

## 入っているもの

| ディレクトリ | 内容 | 状態 |
|---|---|---|
| `seating/` | 名簿から座席表を作って印刷する（Google スプレッドシート＋GAS） | 手配置と印刷まで。自動生成は未実装 |

## 構造のルール

**トップレベルのディレクトリ1つ＝Apps Script プロジェクト1つ。**
道具どうしでコードを共有しない。

共通ライブラリを置くと、校務PCへコピペで持っていく運用が
「どのファイルをどのプロジェクトに入れるか」で必ず壊れる。
道具の数が増えたときに効くのは、共通化ではなく独立性のほう。
重複を許して、1つのディレクトリを丸ごとコピーすれば動く状態を保つ。

各ディレクトリの `README.md` に、その道具の設計の根拠・置き方・使い方を書く。
このファイルには一覧しか書かない。

## 個人情報の扱い（全体の方針）

名簿を扱う道具が多いので、全部に共通で次を守る。

- **`UrlFetchApp` を使わない。**外部への送信経路を作らない
- **HTML から CDN を読まない。**CSS・JS はすべてファイル内に書く。
  外部スクリプトを読むと、名簿そのものは飛ばなくても閲覧のたびに外部へ通信が出る
- **Web アプリとして公開しない**（`doGet` を持たない）。
  URL を知れば校外から到達しうる経路を作らない
- **既存の校務名簿ファイルに直接スクリプトを入れない。**
  他の教員と共有しているファイルがスクリプト付きになり、
  名簿側の列構成が変わるたびに壊れる。
  新しいスプレッドシートを作り、名簿シートに値をコピーして使う
- **児童の評価をデータの値にしない。**
  配置や集計のために属性が要るときは、人格特性ではなく役割の名前で持つ。
  印刷物には出さない。見直した日付を持たせて学期ごとに更新する

## 運用

私用PC・iPhone で編集し、GitHub 経由で校務PCへ持っていく。
校務PC では clasp を使わないので、**Apps Script エディタへのコピペで完結する構成**にする。
1つの道具のファイル数は数個に抑え、貼る順序に依存しないようにする。
