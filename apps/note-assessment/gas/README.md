# ノート評価 — GAS配置

`web/`のノート評価画面をGoogle Apps Scriptに載せたもの。**Step 1〜9 まで実装済み。** シート・スケール・本人確認・記録の読み書き・集計・児童画面・教師画面・一斉入力・学期・出力。手順の全体は [`../docs/implementation-plan.md`](../docs/implementation-plan.md)、仕様は [`../docs/spec.md`](../docs/spec.md)。

## 貼る前に手元で確かめる

```
python3 scripts/build.py                 apps/note-assessment/gas/dist/ を作る・作り直す（貼るのはこの中身）
node apps/note-assessment/gas/scripts/localcheck.js          サーバのコードを走らせて確かめる（181項目）
node apps/note-assessment/gas/scripts/preview.js                    児童画面を1枚の HTML に書き出す
node apps/note-assessment/gas/scripts/preview.js out.png            playwright-core があれば png も撮る
node apps/note-assessment/gas/scripts/preview.js out.png teacher    教師画面を見る
```

`preview.js` は、gas/ のサーバコードをブラウザの中で動かし、`student.html` を実際に描く。`google.script.run` をその場の関数呼び出しに差し替えているだけなので、**画面もサーバも本物**が動く。Google のアカウントも配置も要らない。書き出した HTML はそのままブラウザで開ける。

Apps Script の API を偽物に差し替えて、`.gs` を全部1つのスコープに読み込んで走らせる。GAS も同じく全ファイルが1つのスコープを共有するので、**ファイル間の参照ずれもここで出る**。Google のアカウントは要らない。

タイムゾーンは検査側で `Asia/Tokyo` に固定してある。UTC のまま回すとロックの検査が落ちる。**それは検査の不備ではなく、`appsscript.json` の `timeZone` が要る理由そのもの。**

## ファイル

**貼るのは `apps/note-assessment/gas/dist/` の4本＋マニフェスト。** それ以外はすべて元（`src/`と`generated/`）で、直すのはこちら側。`python3 scripts/build.py` を実行すると `apps/note-assessment/gas/dist/` が作り直される。

| 貼るもの（`apps/note-assessment/gas/dist/`） | 中身 |
|---|---|
| `appsscript.json` | `src/appsscript.json`から複製するマニフェスト |
| `src/Code.gs` | `src/*.gs`と`generated/Scale.gs`をこの順にまとめたもの（**生成物**） |
| `student.html` | 児童画面。`include()` を全部その場に展開ずみ（**生成物**） |
| `teacher.html` | 教師画面（単元ごと／期末評定／設定）。同上（**生成物**） |
| `hello.html` | Step 3 の確認画面。同上（**生成物**） |

**貼らない・直すほう（このフォルダの元）：**

| | |
|---|---|
| `generated/Scale.gs` | スケールの定義（`apps/note-assessment/web/src/scale.js` からの**生成物**） |
| `generated/scale.html` `generated/tokens.html` `generated/material.html` | 同じものをクライアントへ（**生成物**。`dist/*.html` へ展開して使う） |
| `src/Setup.gs` | シート6枚を作る・検算する |
| `src/Config.gs` | 設定シート。5分キャッシュ |
| `src/Roster.gs` | 名簿。メール → 児童ID |
| `src/Master.gs` | 教科・単元・授業マスタ |
| `src/Lock.gs` | ロックの境界。日付欄の文字列も受ける `toDate_` |
| `src/Hours.gs` | 児童が使える時間（8:00〜ロック時刻） |
| `src/Store.gs` | 記録の読み書き。保存はサーバ側で全部確かめる |
| `src/Aggregate.gs` | 単元評価・期末評定の計算と、確定シート |
| `src/Api.gs` | 画面から `google.script.run` で呼ぶ入口 |
| `src/student.html` `src/teacher.html` `src/hello.html` | 画面の元。`<?!= include('…') ?>` が残っている（貼るのは `dist/` のほう） |
| `src/Export.gs` | 通知表用の表の書き出し・シートのメニュー |
| `Code.gs` | `doGet`・役割の判定・`include()` |
| `scripts/localcheck.js` | 手元での検査 |
| `scripts/preview.js` | デプロイせずに児童画面を見る |

**`generated/`と`dist/`は直さない。** `python3 scripts/build.py`が`web/src/`・`shared/ui/`・`gas/src/`から作る。直すと次のビルドで消える。

**なぜ1本にまとめるか。** GAS はもともと `.gs` を全部1つのスコープで読む（ファイルをまたぐ関数呼び出しは元から効く）ので、ファイルを分けても速さも動きも変わらない。**分かれているのは開発のための整理であって、貼るときの都合ではない。** `.gs` が12本・HTML が6本もあると、Apps Script エディタで「＋ → 名前を付ける → 貼る」を18回繰り返すことになり、名前を1つ間違えるだけで `include()` が壊れる。`localcheck.js`で個別ソースを検査し、`python3 scripts/build.py --check`で配布版が同じ正本から再現できることを検査する。

手順書には `eval` でスケールを読む書き方を載せていたが、**トップレベルの `const` が `eval` の外に出ない場合があるので、実ファイルを生成する形に変えた**。中身は同じ1つの元から出ている。

## 置き方

1. スプレッドシートを新規作成する（教師のアカウントで）
2. 拡張機能 → Apps Script
3. ⚙ プロジェクトの設定 →「**`appsscript.json` マニフェスト ファイルをエディタで表示する**」にチェック
   - **先にやる。** 後回しにするとタイムゾーンとデプロイ設定を書けない
4. `apps/note-assessment/gas/dist/` の中身を貼る（無ければ `python3 scripts/build.py` を1回実行して作る）

   | 種類 | 名前 | 貼る中身 |
   |---|---|---|
   | マニフェスト | `appsscript.json` | **既存のものを上書き**（`dist/appsscript.json`。新規作成ではない） |
   | スクリプト | `Code` | `+` → スクリプト → 拡張子なしで `Code` → `apps/note-assessment/gas/dist/Code.gs` の中身を全部貼る |
   | HTML | `student` `teacher` `hello` | `+` → HTML → 拡張子なしでそれぞれ命名 → `apps/note-assessment/gas/dist/` の同名ファイルを貼る |
   | 消してよい | （旧）`授業マスタ` シート | 実施日は使わなくなった |
   | 貼らない | `apps/note-assessment/gas/src/*.gs`（`Code.gs` 以外）・`apps/note-assessment/gas/generated/scale.html` 等・`localcheck.js` `preview.js` `README.md` | 元・手元専用。`dist/` の材料 |

   **貼るのはこれで全部（マニフェスト＋4ファイル）。** 個々の `.gs`（Config・Roster・Master…）は
   `apps/note-assessment/gas/dist/Code.gs` の中に見出しコメント（`/* ==== Config.gs ==== */`）付きで
   全部入っている。あとから特定の処理を探すときは、そのコメントで検索する。

5. `setupSheets` を実行 → シート6枚ができる
   - 初回は「このアプリは Google で確認されていません」が出る。
     詳細 →「（プロジェクト名）に移動（安全ではないページ）」で進む
6. **設定シートの「教師メール」に自分のメールを入れる**
   - 飛ばすと、教師自身が確認画面で「だれか わかりません」と出る。
     判定は名簿と教師メールの2つしか見ていない
7. 名簿・教科マスタ・単元マスタを埋める
8. `clearAllCache` を実行（5分待たずに反映される）
9. **`diagnose` を実行する。** 児童の画面に何が出るか、出ないなら何が足りないかを1画面で出す。ここが全部 ○ になってから児童に渡す
10. デプロイ → 新しいデプロイ → **ウェブアプリ**
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**同じ組織内の全員**

`appsscript.json` に `executeAs: USER_DEPLOYING` / `access: DOMAIN` を書いてあるので、画面の既定もこの組み合わせになる。**それでも一度目で確認する。** ここを間違えると児童全員にシートの編集権限が渡り、あとから直せない。

### 記号を置き換えたとき（1回だけ）

上端を `Z− Z Z+ Z++` から `Z Z+ Y Y+` に変えた。**すでに記録がある場合は、
メニューの「上端の記号を置き換える（1回だけ）」を実行する。**

| 前 | 後 |
|---|---|
| `D−` `D` `D+` `D++` | `D` |
| `C−` `C` | `C` |
| `C+` `C++` | `C+` |
| `Z−` | `Z` |
| `Z++` | `Y+` |

`B` 以上は変わらない。**`D` と `C` を畳んだぶん内部値は動く**ので、
畳んだあとに設定タブで `A下限`／`C上限` を確かめる（既定は `A+` と `C+`）。

`Y` 以上は既定で児童に出ない。設定タブの「Y を児童にひらく」で解放する。

### 児童の画面が空だったら

**`diagnose` を実行する。** よくある原因は次の順。

| 出る症状 | 原因 |
|---|---|
| 教科タブが空・表が出ない | **教科マスタが空**、または `公開` が TRUE でない |
| 「だれか わかりません」 | 名簿にメールが無い／教師メールに自分を入れていない |
| 「きろくを こうしんして います」 | 8:00〜16:00 の外。時間内なら `diagnose` でタイムゾーンを確かめる |

児童には「せんせいに つたえてください」としか出さない。**教師が同じ URL を開くと、直し方のほうが出る。**

### 詰まりやすいところ

**URL は `/exec` を使う。** エディタの「テスト用デプロイ」で取れる `/dev` の URL は、**編集権限のある人しか開けない**。児童アカウントでの確認には使えない。

**コードを直しても URL の中身は自動では変わらない。** デプロイを管理 → 鉛筆マーク → **バージョンを「新バージョン」に変えて**デプロイし直す。「直したのに変わらない」の原因はたいていこれ。「新しいデプロイ」を選ぶと URL 自体が変わるので、**同じ URL を保つなら「編集」のほう**。

## Step 3 の確認（ここが通らなければ先へ進まない）

デプロイした URL を **児童アカウント1つで実際に開く**。

| 出るはず | 意味 |
|---|---|
| こんにちは、◯◯ さん／児童 | メールが取れて名簿と照合できた |
| メール欄に本人のアドレス | `Session.getActiveUser().getEmail()` が通った |
| 見える教科：算数、国語 | 非公開の教科が児童に渡っていない |
| 往復テスト：○ | スケールがサーバ・クライアント両方で同じ |

**「メールが取れていない」と赤く出たら、そこで止める。** 組織のポリシーで `getActiveUser()` が空を返す設定になっている。以降の設計（本人確認・ロック・貫通）がすべてこの1点に乗っているので、先に進んでも積み上がらない。

教師アカウントで開くと「先生／教師」、名簿にも教師メールにも無いアカウントでは「だれか わかりません」と出る。**3つとも試す。**

## 保存のときサーバが確かめること

`Store.save` は画面から来た値を1つも信用しない。

1. **児童IDを呼び出し元のメールから引き直す。** 画面が渡してきたIDは使わない
2. **ロックをサーバで判定し直す。** 端末の時計は児童が変えられる
3. **開室時間を確かめる。** 16:00〜8:00 は断る
4. **教科の公開を確かめる。** 非公開の教科には書かせない
5. **時数の範囲を確かめる。** 範囲の外の授業には書かせない
6. **`Y` 以上は解放されるまで断る。** 教師設定で解放するまで児童は入れられない
7. **`/` は教師だけ。** 画面に出さないのは誘導であって権限ではない
8. `LockService` で囲む。29人が同時に押す

教師は `saveAs` を使い、1〜6を貫通する代わりに `更新者` に必ずメールが残る。

## 児童画面の動き

- 押した瞬間に画面へ反映し、サーバが断ったら**元の値に戻して**理由を出す。
  Chromebook から往復1〜2秒かかるので、待たせると連打される
- 1タップで作り直すのはそのセルだけ。表全体は作り直さない（実測 148ms → 4ms）
- **「のこり ◯」は済んだ授業の中だけ数える。** 済んだかどうかは学級の入力から引く
  （3人以上が入れている最大の No まで＝`Store.taughtUpTo`）。線が引けていないうちは
  何も出さない。まだ習っていない授業まで数えて赤で「未入力 48」と出ていたのを直した
- **授業ごとの学級平均は教師が見るときだけ**セルの下に出す（`B++　6人`）。
  児童には画面で隠すのではなく、サーバが送らない
- **授業の表も単元カードも学期ごとに畳む。** 既定で開くのは今月の学期だけ
  （4〜7月＝1学期、8〜12月＝2学期、1〜3月＝3学期）。開閉は**両方で共有**する
- 畳んだ学期の見出しに「未入力 ◯」を出す。上の badge は教科ぜんぶの数なので、
  畳むと在りかが見えなくなる
- 60秒ごとに読み直す。16:00 をまたいだら閉室の画面に切り替わる
- 開いている時間の残りが10分を切ると「あと ◯ふんで、きょうは おしまいです」
- **待たせるあいだは画面を覆う**（読み込み・教科の切り替え）。覆いの下は触れないので連打が起きない
- **1マスの保存では覆わない。** 押した瞬間に反映するのが要点なので、そこで止めると
  転写がかえって遅くなる。代わりに**そのマスだけ**往復のあいだ受け付けない

### 速さのために入れてあるもの

| | 効き方 |
|---|---|
| 選択肢はマスを触るまで作らない（`fillOptions`） | 組み立て 186ms → **9ms**、`option` 1,051 → 70 |
| 表は1回の `innerHTML` で組み立てる | 要素数 1,911 → **514** |
| 畳んだ学期のセルは作らない | 1学期だけ開いた状態で **294 要素**・`option` 30 個 |
| 聞き役は表に1つだけ（イベント委譲） | 70個へ付ける手間が消える |
| 記録を児童ごとに 30分キャッシュ（`Store.recOf`） | 29名のうちシートを読むのは1人目だけ |
| 保存したらキャッシュを**捨てずに差し替える**（`touchCache_`） | 1回保存するたびの読み直しが消える。検査で実測 |
| 学級集計は児童ごとのキャッシュから組み直す（`Store.lessonStats`） | 授業ごとの平均と「済んだ授業の線」がシート読みなしで出る |
| 60秒ごとの確認は時刻だけ見る（`apiTick`） | 毎分の空読みが 29台ぶん消える |

**キャッシュが無くても動く**（その場でシートを読む）。正しさはシートが持っている。

## 「単元の評価をする」を押したとき

旗を立てるだけでは児童の画面に何も出ない。確定シートに値が無いからで、
押した本人には「押したのに変わらない」としか見えない。
**押した時点で仮値を採用してから見せる。** すでに教師が直した値は残す。

**採用されるかどうかは児童1人ごとの記入率で決まる。学級全体では見ない**
（`apiSetRated` / `apiAdoptAll` がサーバ側で見る。`RATE_MIN` / `meetsRate_`、Api.gs）。
母数が小さい代表値は1つの記号で大きく動くため、その児童自身が8割埋めるまで
採用しない。**押す操作自体はいつでもできる。** 学級全体の記入率で止めると、
足の速い児童まで足の遅い児童に合わせて止めてしまうため。

- 8割未満の児童は、押しても採用されずに残る（あとで追いついたら拾われる）
- `adopted`（採用した人数）と `skipped`（記入率不足で見送った人数）を返す。
  記入が1つも無い児童（仮値が無い）はどちらにも数えない
- `apiUnitTable` の各行に `ready`（この児童が採用の水準か）を返し、
  画面は押す前から「入力」列に印を付ける
- 学級全体の記入率（`fillRate`）も返すが、これは目安の表示だけで判定には使わない
- **「もどす」は記入率を見ない。**

## 教師画面

`?p=teacher` で開く。児童画面の教師表示からもリンクが出る。**リンクを出さないのは
誘導であって権限ではないので、飛んだ先でも役割をメールから判定し直している。**

| タブ | できること |
|---|---|
| 単元ごと | 29人 × 単元の一覧、仮値と**学級差**、採用、一斉入力、「単元の評価をする」 |
| 期末評定 | しきい値のもとでの仮評定、分布と目安、採用、通知表用の表の書き出し |
| 設定 | いまの状態（diagnose）、しきい値と時刻、教科の追加と公開・時数・開始No、単元の範囲・色・学期、`Y` の解放、シートへのリンク |

**`学級差` は学級の中央値から何段ずれているかを出す。** 2段以上だけ濃く出るので、
29人を1人ずつ見比べずに、外れているところだけ見に行ける。

**「入力のならび」の1マス（chip）は押せる。** 誤って入れた記号がロック後に
気づいたときの入口。押すとその場でプルダウンが出て、選ぶと即時に
`apiSaveAs` でロックを貫通して直る。確認は挟まない（誤ればもう一度押せばよい）。
直したマスは下線の印が付く（`edited`。児童画面の `.cell.edited` と対）。

これは元々 `Store.saveAs` としてサーバ側にはあったが、呼び出す画面が無かった
（実装の抜け）。抜けている間は、記録シートを手で開いて行を探し書き換え、さらに
`clearAllCache()` を実行しないと直った値が反映されない状態だった。

**最初に見るのは設定タブの「いまの状態」。** 児童の画面に何が出るか、出ないなら何が
足りないかがそのまま並ぶ。

### 教科ごとの開始No

授業番号は既定で No.1 から始まるが、教科マスタの「開始No」列（既定 1）で変えられる。
紙のノートで既に何時間か進めていて、続きの番号（例：No.16）からこの道具を
使い始めたい、という場合のため。設定タブ「教科」の表で、時数と並べて編集する。

- **サーバ側でも範囲 `[開始No, 開始No + 時数 − 1]` を確かめる**（`Store.save`/`saveAs`）
- 単元の範囲（開始No・終了No）は自動では動かない。開始Noを変えたら、
  「いまの状態」の検算（どの単元にも入らない授業）で確かめる
- 既存のシートに「開始No」列が無くても動く（無ければ 1 として扱う）
