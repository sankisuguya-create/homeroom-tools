# グループ分け — 設計の決定

## 決めたこと
| 決定 | 理由 |
|---|---|
| 1ファイルのHTML、外部通信なし、保存は localStorage | 氏名を扱う（設計理念「個人情報を外部に送信しない」）。build.py の外部参照検査の対象 |
| 名簿はスプレッドシートの範囲を貼る（GAS で直接読まない） | 利用者の選択（2026-11）。デプロイ・版ずれの管理が要らない。読み取りは child-support の paste.js を共有し、見出しの言い換え・校務システムの書き出し（姓＋名の列）もそのまま読む |
| 児童の鍵は「組-番号」 | 名簿を貼り直しても欠席・離す組合せが同じ児童に付いたまま残る |
| 割り切れない分は指定人数＋1の組にする（指定より少ない組は作らない） | 利用者の選択。人数の多い組の位置は毎回ランダム |
| 人数を変える・欠席を押す・名簿を入れ替えると、その場で組み直す | 古い人数の案が残ると、映っている案と設定が食い違う |
| 名前の出し方・班の名前の切り替えでは組み直さない | 見た目の切り替えで案が変わると、決めた組を失う |
| 離す組合せは重み1000、前回の相手は重み1の入れ替えの山登りで直す | 離す組合せは必ず守る側、前回は「なるべく」。40人程度なら4000回の入れ替えで一瞬（体感の待ちなし） |
| 「前回」＝3分より長く映した案 | 組み直しを何度か押して捨てた案を「前回」にしない。参照している前回の日時は設定欄に出す（状態を隠さない）。3分は根拠なし（運用で調整） |
| 「◀ 前の案に戻す」（20案まで） | 押しすぎて気に入った案を失うのを防ぐ。確認ダイアログは出さない（期待損失が小さい） |
| スペースキーはフォーカスの位置によらず「組み直す」 | 直前に押したボタン（前の案に戻す等）がスペースで押し直されるのを防ぐ。文字を書く欄だけ除く |
| 枠は色で分けず、濃い枠線と余白で分ける | 組の数は最大22（45人を2人組）で、見分けられる色の数を超える。投影で淡い線は飛ぶ |
| 文字の大きさは全部の枠で同じ。外の列数×枠の中の列数を総当たりで、最大になる組を選ぶ。字幅の目安で決めた後、実寸ではみ出す間は 7% ずつ縮める | 枠ごとに大きさが違うと「大きい班」に見える（ui-layout の U） |
| モニターは別の窓（教室の時計と同じ方式） | 操作の部品をモニターに出さない |
| 名字は空白で切る。空白の無い名前はフルネームで出し、その人数を見本の下に出す | 姓と名の境目は機械では決められない |
| 同じ名字は名の1字目を添える | 「名字だけ」で同じ名字の2人が区別できないため |
| 番号は、名簿に組が2つ以上ある時だけ「組-番号」 | 1学級なら番号だけで足りる |

## 入れなかったもの
- 男女・学力を均す組分け：依頼に無い。入れるなら名簿の性別列（paste.js が読める）で足せる。
- 組の名前の自由な名付け（色・動物など）。

## 確かめていないこと
- 学校の教師用端末での、モニター側の窓の自動配置と全画面（教室の時計と同じ）。
- 教室の後ろの席から読める大きさか（1920×1080 で4人組×8組のとき 67px）。
