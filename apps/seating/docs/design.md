# 席替え 設計

目的：教員の時間と認知資源の節約、および人力では解けない組み合わせ問題（条件つき配置）の計算。
形態：Google スプレッドシートにバインドした Apps Script（メニュー「席替え」＋大きなダイアログ）。

---

## 0. 参照した同系統アプリと取り込んだ機能

根拠：各アプリの公開説明（記憶ベース。2026-09 時点で再確認していない＝根拠弱）。

| 系統 | 例 | 取り込んだ機能 | 取り込まなかった機能 |
|---|---|---|---|
| くじ・抽選型 | 席替えアプリ各種（スマホ/Web） | 固定席、前方希望、男女交互、発表の演出 | 完全ランダムのみの生成 |
| 条件最適化型 | 席替えメーカー系 Excel マクロ、海外の Seating Chart 系（離す/近づける ペア指定） | 離すペア・近くペア、前回と同じ隣の回避、複数回の履歴 | 成績（学力）の均等化※ |
| 学級管理統合型 | Class Charts / Seating Chart Maker 等 | 教師側視点と児童側視点の反転表示、手動の入れ替え、班編成 | 行動ポイント連動 |

※学力値の入力は評価情報を座席用シートに複製させることになり、漏えい時の害が大きい。代わりに「配慮（分散）」フラグ1つで同じ効果の大半を得る。

---

## 1. 初版設計（v0）

- シート：名簿・条件・配置・設定・履歴・座席表。
- 生成：サーバ側（GAS）で焼きなまし法、結果を座席表シートに書くだけ。
- 条件：離す／近く／男女／前方／固定／履歴。
- UI：サイドバーにボタン「作る」。

## 2. 自己批判

| # | 問題 | 含意 |
|---|---|---|
| 1 | 結果を**シートに書くだけ**だと、教員は気になる所を手で直す→直すたびに条件を頭で再点検する。 | 認知負荷を減らすという主目的に反する。手直しの瞬間こそ計算の助けが要る。 |
| 2 | 条件を満たせないとき、**何が衝突したか**が出ない。 | 教員は条件を1つずつ外して試す＝最も時間を食う作業が残る。 |
| 3 | サーバ側計算は 6 分制限・往復遅延があり、候補を何度も出し直しにくい。 | 試行回数が減り、最適化の利点が出ない。 |
| 4 | サイドバー（幅 300px）では座席グリッドが読めない。 | 大きいモードレスダイアログにする。 |
| 5 | 配置を独自エディタで作らせると学習コストが増える。 | 教員が既に使えるのは「セルに数字を書く」操作。配置はシートに班番号を書くだけにする。 |
| 6 | 生成のたびに履歴へ書くと、没案が履歴を汚し「前回」が壊れる。 | 履歴は「決定」時のみ書く。 |
| 7 | 1案だけ出すと、評価関数に載らない事情（担任しか知らない関係）を比べられない。 | 複数候補を並べ、差分の違反だけ見せる。 |
| 8 | 配慮情報・離すペアが印刷物や掲示に漏れる危険。 | 座席表シート（印刷・掲示用）には氏名と番号のみ。理由はダイアログ内だけで表示。 |
| 9 | 「隣」の定義が曖昧。日本の教室は2人組の机が多く、横に接した机が最も強い関係。 | 隣（横接）・前後・斜め・同じ班の4段階で重み付け。 |
| 10 | 条件の書き間違い（氏名の表記ゆれ）で黙って無視される。 | 条件は番号で書く／氏名でも可、解決できない行は事前検査で名指しする。 |
| 11 | 1年を通した**場所の偏り**（ずっと後ろ・ずっと窓側）が人力では追えない。 | 履歴から前方率を集計し、偏りをコスト化。 |
| 12 | 抽選演出で最適化結果を「くじ」と称すると児童に虚偽を示す。 | 演出は「発表」（順に表示）とし、くじとは称しない。 |

## 3. 再設計（v1：実装する版）

### 3.1 構成

```
スプレッドシート
 ├ 名簿   番号|氏名|性別|在籍|前方|固定席|班長|配慮|メモ
 ├ 条件   番号A|番号B|関係(離す/近く)|強さ(必須/できれば)|メモ
 ├ 配置   セルに班番号＝座席、空白＝通路。1行目は「前（黒板）」
 ├ 設定   キー|値
 ├ 履歴   決定日|回|番号|氏名|行|列|班   ← 決定時のみ追記
 └ 座席表 印刷・掲示用（児童から見た向き＋教卓から見た向き）
Apps Script
 ├ Code.gs      メニュー・シート初期化・入力読取と検査・決定の書込
 └ Dialog.html  UI＋solver（ブラウザで計算）
```

計算はブラウザ（ダイアログ内）で行う（批判3）。サーバは読み書きだけ。

### 3.2 座席と関係

- 座席＝配置シートで値の入ったセル。値＝班番号。
- 隣：同じ行で左右に接した座席（間に空白なし）。
- 前後：同じ列で上下に接した座席。
- 斜め：対角に接した座席。
- 同班：班番号が同じ。
- 前方：前から `前方の行数` 行以内の座席（空行は数えない）。

### 3.3 コスト（小さいほど良い）

必須条件は重み 100000（事実上の制約）。違反は必ず文章で列挙。

| 項目 | 既定重み |
|---|---|
| 固定席 | 構造で保証（入れ替え対象外） |
| 前方の児童が前方外 | 必須 |
| 離す（必須）が隣・前後・斜め・同班 | 必須 |
| 離す（できれば） | 隣 60／前後 40／斜め 20／同班 30 |
| 近く（必須）が隣・前後・同班のどれでもない | 必須 |
| 近く（できれば） | 30 |
| 男女：隣が同性（モード「隣は男女」） | 20 |
| 男女：縦横接が同性（モード「市松」） | 10 |
| 班の男女差が2以上 | 10×超過 |
| 班長：班長候補がいない班 | 40／2人以上 12×超過 |
| 配慮：同じ班に2人以上 | 40×超過／隣接 30 |
| 履歴：k 回前に隣だった | 50×0.6^(k-1) |
| 履歴：k 回前に同班だった | 12×0.6^(k-1) |
| 履歴：前回と同じ席 | 15 |
| 場所の偏り：過去の前方率が高いのに前方 | 20×(前方率−平均) |

### 3.4 探索

- 焼きなまし（2席の入れ替え、固定席は除外）。空席は仮想児童で埋める。
- 差分計算：入れ替えた2席に関わる項のみ再計算。
- 候補3案を別シードで生成し、互いに似すぎたら破棄。
- 乱数はシード付き（再現と検査のため）。

### 3.5 UI（ダイアログ）

1. 開くと入力検査。致命的な問題（席不足・固定席重複・前方席不足）は名指しで表示し生成しない。
2. 「作る」→ 候補 A/B/C のタブ。各タブに総合点と「気になる点」一覧。
3. 座席をタップ→別の座席をタップで入れ替え。即時に再採点し、増えた違反を赤で示す。
4. 固定：座席を長押し（または「固定」ボタン）で、その回だけ固定して再生成できる。
5. 向き切替：黒板側から／教卓側から。
6. 「決定」→ 座席表シートを書き、履歴に追記。
7. 「発表」→ 番号順に1人ずつ表示（全画面、投影用）。

### 3.6 やらないこと

- 学力値による均等化（理由は §0）。
- Classroom 連携（API 不可）。
- 児童端末からの利用（教員のみ）。

## 4. 残課題（後続で着手）

- 複数学級・学年単位での運用（シートのコピーで足りる想定。根拠なし）。
- 班内の役割（班長・副班長…）の割当。
- 履歴からの「これまでの隣の回数」行列の可視化。
