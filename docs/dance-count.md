# ダンスカウント表

運動会・学芸会の集団演技の振り付けを、8カウント単位で書き起こして紙にする道具。
`prototypes/dance-count.html` をブラウザで開くだけで動く。サーバもビルドも要らない。

## 何を解いているか

振り付け表は普通、動きの絵と歌詞を並べた手書きの紙で回る。この形には決まった弱点がある。

**歌詞と拍の対応が読み取れない。** 印刷された歌詞の下に「1・2・3・4・5・6・7・8」を手で書き足しても、
文字幅が揃わないので、どの言葉がどの拍かは書いた本人にしか分からない。
学年で共有した瞬間に、人によって違うカウントで教えることになる。

だからこの道具は、**カウントの枠を先に等分で置き、その枠の中に言葉を入れる**。
ずれようがなくなる。

## 決めたこと

| | |
|---|---|
| 単位 | 1行＝1エイト（8拍・2小節）。ダンス指導の現場の数え方に合わせる |
| ブロック | 曲の構成（イントロ・Aメロ・サビ・間奏）に対応。長さは 8×1〜8×4 から選ぶ |
| 1エイトの中身 | 上段＝その8カウントで歌う言葉やかけ声。下段＝1〜8それぞれの動き |
| ブロックの脇 | 動き・隊形。文章で書く。絵は紙に手で描く前提で、枠だけ空けてある |
| タイム | BPMから自動計算。各ブロックが曲の何分何秒から始まるかが出る |
| 保存 | ブラウザ内（localStorage）。打つたび自動 |
| 持ち運び | JSONの書き出し・読み込み。私用PCと校務PCの間はこれで渡す |
| 紙 | A4横。ブロックは途中で改ページされない |

## 決めなかったこと

**複数曲を同時に持たない。** 1つのブラウザに1枚。曲を替えるときはJSONを書き出してから作り直す。
タブや曲一覧を足すと、年に1〜2回しか使わない道具の操作を覚え直すことになる。

**サーバに置かない。** GAS も Google スプレッドシートも使わない。
振り付けを書くのは教師1〜数人で、同時編集の必要がない。

**曲のデータを同梱しない。** 中身が空の道具だけを置く。理由は次の節。

## 歌詞の扱い

市販曲の歌詞は著作権で保護されている。訳詞も同じで、原曲の旋律がパブリックドメインでも
日本語詞は別に保護される（例：唱歌「ピクニック」の旋律は民謡由来のPDだが、訳詞は保護下）。

運動会・学芸会は**特別活動＝教育課程内**なので、著作権法35条の「授業」に含まれる。
したがって、

- 校内で使う指導資料に歌詞を書き写し、教職員・児童に配る → **35条の範囲内**
- その資料を公開リポジトリ・Webページ・SNSに載せる → **範囲外**

**このリポジトリは公開設定なので、歌詞を入れたJSONはコミットしない。**
道具（空のHTML）だけを置き、中身は各自の端末とJSONで持つ。
非公開の置き場が要るなら、リポジトリを private にするか、別の private リポジトリを作る。

## BPMの測り方

音源に合わせて手拍子を打ち、15秒間の拍数を数えて4倍する。
入力すると1エイトの秒数と全体の長さが出るので、**曲の実尺と突き合わせて検算できる**。
合わなければBPMかブロック数のどちらかが違う。

パンク系の曲はBPM表記が倍取り（例：259）になっていることがある。
踊る側が数えるのはその半分（130前後）。

## 直すとき

元は `prototypes/src/dance-count.html`。`python3 build.py` で `prototypes/dance-count.html` が出る。
色トークンは `prototypes/src/tokens.css` から `@include` で入るので、この道具の中に色の値は書かない。
`prototypes/dance-count.html` を直接編集しても次のビルドで消える。
