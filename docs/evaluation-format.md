# 授業評価・単元評価の設計メモ

2026年度 3年3組（29名）向け。児童がノートの記号をサイトに転写し、その蓄積から単元評価を組み立てる仕組みの設計決定を記録する。

## 1. 評価スケール

9段階の順序尺度。記号自体に意味はなく、順序だけが情報を持つ。

| 内部値 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|
| 記号 | D | C | B | B+ | A | A+ | A++ | Z | Z+ |

- 記号は児童の意欲を引き出すための便宜的な名称。A系列から外れた Z / Z+ は、その希少性が動機づけとして働く。**記号は変更しない。**
- 内部値（1〜9）は集計にのみ使う。**児童には数値を見せない。** 序列を数値化して提示すると動機づけ装置としてマイナスに働く。

### 色の規約

記号が順序を語らないため、色が順序を担う唯一の冗長チャネルになる。したがって色は**必ず単調勾配**であること。

紙の運用で使っていた「赤(D,C) → 青(B,B+,A) → 黄(A+,A++) → 赤(Z,Z+)」は色相が循環しており、最下位と最上位が同じ赤になる。児童が帯から記号を探す際に下位と上位の両方へ誘導するため、サイトでは採用しない。

サイトの配色は淡青灰 → 藍 → 菫の一方向勾配。上位3段（A++ / Z / Z+）にのみ金の縁取りを付けて希少性を演出する。縁取りは勾配を壊さない装飾なので許容する。

### 教師用アンカー（未記入）

9段階の隣接境界を1行で言語化した規準。**児童には見せない。教師の判定安定化のためだけに使う。**

規準がないと、同じ記号が時点間で同じ水準を指す保証がない（評価者内ドリフト）。単元後半ほど期待水準は上がるため、ドリフトは児童の伸びを打ち消す方向に働く。70時間分を単元評価に集約する以上、これは無視できない。

| 記号 | 規準（1行） |
|---|---|
| Z+ | *未記入* |
| Z | *未記入* |
| A++ | *未記入* |
| A+ | *未記入* |
| A | *未記入* |
| B+ | *未記入* |
| B | *未記入* |
| C | *未記入* |
| D | *未記入* |

埋める過程で「A+ と A++ の違いを一文で書けるか」の判定が同時に済む。書けない隣接段は統合を検討する。

## 2. 授業マスタ

| 列 | 内容 |
|---|---|
| No | 1〜70（写真の一覧表と同じ通し番号） |
| 単元 | 九九の表とかけ算 / わり算 / たし算とひき算の筆算 / 時こくと時間 … |
| 時 | 単元内の第n時 |
| 観点 | 知識・技能 / 思考・判断・表現 / 主体的に学習に取り組む態度 |

観点は単元計画時に教師が一括で付ける。児童の操作は変わらない。単一序列は観点を保持しないため、これがないと学期末に観点別へ分解できない。

## 3. 単元評価の集約

順序尺度なので**平均は取らない**（D→C の幅と A+→A++ の幅が等しい保証がないため）。

サイトは以下を並記し、教師が採用または修正する。

| 指標 | 意味 | 扱い |
|---|---|---|
| 後半1/3の中央値 | 単元終盤の実力 | **仮値の既定** |
| 全時間の中央値 | 単元通しての安定水準 | 併記 |
| 最高到達 | 一度でも届いた上限 | 併記 |
| 下位帯（D/C）の回数 | つまずきの残存 | 併記 |

後半重みを既定にする根拠：単元は積み上げ構造なので、序盤の低評価は未習の反映であって到達度ではない。ただしこれは仮定であり、教師が全期間中央値に切り替えられるようにする。

## 4. 画面

### 児童（転写）
1画面1操作。名前を選ぶ → 未転写の授業だけが1件ずつ出る → 9段の帯から記号をタップ → 決定。
転写済みは表示しない。残り件数だけ見える。

「1人学習が全般にしんどい児童がいる」（学級DB 2026年度）ため、スクロールも複数同時操作も要求しない。

完了後に自分の記号の推移を折れ線で見せる。これが動機づけ装置として働く。

### 教師
1. 70 × 29 の一覧表
2. 単元評価：仮値と4指標を並記 → 採用 / 修正
3. 授業マスタ（No・単元・時・観点）の編集

## 5. 実装方針

- Google Apps Script + スプレッドシート。Classroom API は使わない。
- 保存先：スプレッドシート1枚（行＝児童、列＝授業No）＋ 授業マスタシート。
- 児童端末：CZ1104FM2A（Chromebook）。タッチ操作を前提に、タップ標的は十分な大きさを確保する。
