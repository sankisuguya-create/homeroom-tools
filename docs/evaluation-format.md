# 授業評価・単元評価の設計メモ

2026年度 3年3組（29名）向け。児童がノートの記号をサイトに転写し、その蓄積から単元評価と期末評定を組み立てる仕組みの設計決定を記録する。

**評価する観点は「主体的に学習に取り組む態度」。** 粘り強さ・自己調整・やる気をノートの記述から見取る。到達度ではない。

スケール・ロック・集約の現行仕様は `prototypes/scale.md` が正本。以下は経緯を含む設計メモ。

## 1. 評価スケール

9段階の順序尺度。記号自体に意味はなく、順序だけが情報を持つ。ただし**等質な1本の序列ではなく、機能の異なる3層でできている**。

| 内部値 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|
| 記号 | D | C | B | B+ | A | A+ | A++ | Z | Z+ |

- 記号は児童の意欲を引き出すための便宜的な名称。**記号は変更しない。**
- Z / Z+ は「A++ ではもう凄さを表現しきれない」場面のために後から足された天井突破の記号。A系列の上限を超えたことを示す。
- 内部値（1〜9）は集計にのみ使う。**児童には数値を見せない。** 序列を数値化して提示すると動機づけ装置としてマイナスに働く。

### 3層構造

| 層 | 段 | 機能 | 頻度 |
|---|---|---|---|
| 警告 | D, C | 行動への介入。到達度の記述ではない | 低（意図してつける時のみ） |
| 通常 | B, B+, A, A+, A++ | 到達度 | **A と B+ が最頻** |
| 突破 | Z, Z+ | 要求水準をはるかに超過 | 稀 |

層が違えば意味の種類が違う。特に **D は「到達度が低い」ではなく「やるべきことをしていない」**＝取り組みの記述で、到達度は測定されていない。この一点が集約規則と観点別集計の両方に効く（3節）。

**未解決の懸念**：C を警告に使っているため、「取り組んだが届かなかった」を警告なしに表す段が B ひとつしかない。B の下は即警告帯になる。実務で詰まるようなら B と C の間に1段要る。判断は運用実感による。

### 色の規約

記号が順序を語らないため、色が順序を担う唯一の冗長チャネルになる。したがって色は**必ず単調勾配**であること。

層が3つあるので、**層内は単調勾配、層間は色の種類そのものを変える**。これで層の境界が一目で立ち、層内の順序も保たれる。

| 層 | 表現 |
|---|---|
| 警告（D, C） | 赤のベタ塗り。D が濃く、C が淡い。装飾は一切与えない |
| 通常（B, B+） | 青のベタ塗り。淡→濃 |
| 通常（A, A+, A++） | 金属的な光沢。A → A++ で光沢が強くなる。A++ には金の縁と控えめな粒 |
| 突破（Z, Z+） | ホログラムのラメ。Z は銀藍、Z+ は虹。回転する膜・流れる光・またたく粒 |

A系列と Z系列は「豊かさ」が段ごとに単調に上がる。**豊かさ自体が順序情報**として働くので、記号を読まなくても上下が分かる。

層の切れ目（C のあと、Z のまえ）は帯の余白を広げて示す。文字ラベルは足さない。

紙の運用の「赤(D,C) → 青(B,B+,A) → 黄(A+,A++) → 赤(Z,Z+)」は、Z系がベタ塗りの赤だと最下位と同じ色になり混同する。Z系をラメにすれば素材が別物になるため、D/C を赤にしても混同は起きない。

### 教師用アンカー（未記入）

9段階の隣接境界を1行で言語化した規準。**児童には見せない。教師の判定安定化のためだけに使う。**

規準がないと、同じ記号が時点間で同じ水準を指す保証がない（評価者内ドリフト）。単元後半ほど期待水準は上がるため、ドリフトは児童の伸びを打ち消す方向に働く。70時間分を単元評価に集約する以上、これは無視できない。

以下は聞き取りから起こした暫定版。**要確認：** 実際の判定と合っているかは担任の確認が要る。

| 記号 | 規準（1行） | 層 |
|---|---|---|
| Z+ | 要求水準をはるかに超え、その中でもさらに抜けていた | 突破 |
| Z | 要求水準をはるかに超えた | 突破 |
| A++ | A系列の上限。これ以上ないほどよくできた | 通常 |
| A+ | めあてを達成し、さらに上乗せがあった | 通常 |
| A | めあてを達成した（**最頻**） | 通常 |
| B+ | めあての中心はできた（**最頻**） | 通常 |
| B | 一部できた | 通常 |
| C | 到達していない（警告としてつける） | 警告 |
| D | やるべきことを何もしていない（警告としてつける） | 警告 |

埋める過程で「A+ と A++ の違いを一文で書けるか」の判定が同時に済む。書けない隣接段は統合を検討する。

## 2. 授業マスタ

| 列 | 内容 |
|---|---|
| No | 1〜70（写真の一覧表と同じ通し番号） |
| 単元 | 九九の表とかけ算 / わり算 / たし算とひき算の筆算 / 時こくと時間 … |
| 時 | 単元内の第n時 |
| 観点 | 知識・技能 / 思考・判断・表現 / 主体的に学習に取り組む態度 |

観点は単元計画時に教師が一括で付ける。児童の操作は変わらない。単一序列は観点を保持しないため、これがないと学期末に観点別へ分解できない。

## 3. 単元評価の集約

順序尺度なので**平均は取らない**（D→C の幅と A+→A++ の幅が等しい保証がないため）。

**D は到達度の計算からすべて除外する。** D は「やるべきことを何もしていない」であって到達度が低いのではなく、到達度が**欠測**している。含めたまま中央値を取ると、実力の代表値が取り組み状況に汚染される。C は「到達していない」＝到達度データとして有効なので含める。

副産物として観点別集計の破綻も解ける。「知識・技能」の観点が付いた授業に D が出ても、それは知識・技能のデータではない。D を除外すれば観点別集計が汚れない。

サイトは以下を並記し、教師が採用または修正する。

| 指標 | 意味 | 扱い |
|---|---|---|
| 後半1/3の中央値（D除外） | 単元終盤の実力 | **仮値の既定** |
| 全時間の中央値（D除外） | 単元通しての安定水準 | 併記 |
| 最高到達 | 一度でも届いた上限 | 併記 |
| Z以上の回数 | 天井突破の回数 | 併記 |
| C の回数 / D の回数 | 未到達 / 未着手 | **警告として別枠。到達度指標と混ぜない** |

後半重みを既定にする根拠：単元は積み上げ構造なので、序盤の低評価は未習の反映であって到達度ではない。ただしこれは仮定であり、教師が全期間中央値に切り替えられるようにする。

## 4. 画面

### 児童（転写）
1画面1操作。名前を選ぶ → 未転写の授業だけが1件ずつ出る → 9段の帯から記号をタップ → 決定。
転写済みは表示しない。残り件数だけ見える。

「1人学習が全般にしんどい児童がいる」（学級DB 2026年度）ため、スクロールも複数同時操作も要求しない。

完了後に自分の記号の推移を折れ線で見せる。これが動機づけ装置として働く想定だが、3年生がこれを「自分の伸び」として読めるかは未検証。読めなければ「前回より上がった / 同じ」の一言に差し替える。

**最頻値（A・B+）を強調するような誘導はしない。** これは選択ではなく転写なので、誘導は誤写を増やすだけ。

### 教師
1. 70 × 29 の一覧表
2. 単元評価：仮値と4指標を並記 → 採用 / 修正
3. 授業マスタ（No・単元・時・観点）の編集

## 5. 実装方針

- Google Apps Script + スプレッドシート。Classroom API は使わない。
- 保存先：スプレッドシート1枚（行＝児童、列＝授業No）＋ 授業マスタシート。
- 児童端末：CZ1104FM2A（Chromebook）。タッチ操作を前提に、タップ標的は十分な大きさを確保する。

## 6. ロック

毎日の定時（既定 17:00）に、その日入力された評価を確定する。児童は以後書き換えられない。

実装は**時刻の関数**で行う。保存時刻が直近の境界より前ならロック済み、という判定を毎回引く。日次トリガでフラグを立てる方式はトリガが落ちた日に穴が空くうえ、シートとフラグの不整合を生むので採らない。詳細は `prototypes/scale.md`。

教師アカウントはロックを貫通して編集でき、貫通した変更にはセルに印が残る。
