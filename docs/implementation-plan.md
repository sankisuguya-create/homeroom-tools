# GAS 実装手順

プロトタイプ（`prototypes/`）を Google Apps Script + スプレッドシートに載せる手順。仕様の正本は `prototypes/scale.md`。

## 0. 先に読むところ

**手順1のデプロイ設定を間違えると、あとから直せない。** 児童にスプレッドシートの編集権限が渡り、記録を直接書き換えられる形になる。ここだけは最初に確定させる。

未実装の要件が1つある。**単元の学期設定と、期末評定を学期ごとに出す機能**（`prototypes/teacher-view.html` にまだ入っていない）。手順8で作る。

---

## 1. デプロイの形

Web アプリとして公開する。設定は次の組み合わせだけが正しい。

| 項目 | 値 |
|---|---|
| 次のユーザーとして実行 | **自分**（教師のアカウント） |
| アクセスできるユーザー | **同じ組織内の全員** |

**「アクセスしているユーザーとして実行」にしてはいけない。** その場合スプレッドシートへの書き込みが児童の権限で行われるため、児童全員にシートの編集権限を渡すことになる。渡した瞬間、児童はサイトを経由せず直接シートを開いて他人の評価を書き換えられる。ロックも本人確認も無意味になる。

「自分として実行」でも、**同一 Workspace ドメイン内であれば `Session.getActiveUser().getEmail()` で誰が開いているかは取れる**。これが本人確認の土台になる。シートは教師だけが持ち、児童はサイトしか触れない。

タイムゾーンを `appsscript.json` で固定する。ロックが時刻の関数なので、ここがずれると全部ずれる。

```json
{ "timeZone": "Asia/Tokyo" }
```

**手順3まで進んだ時点で、児童アカウント1つで実際に開いて `getEmail()` が取れることを確認する。** 取れなければ以降の設計が成立しないので、ここで止めて組織のポリシーを確認する。

## 2. スプレッドシートの構造

シート5枚。教師だけが所有する。

### 設定

| キー | 値の例 |
|---|---|
| 学級 | 3年3組 |
| 年度 | 2026 |
| ロック時刻 | 17:00 |
| A下限 | A+ |
| C上限 | C++ |
| 代表値 | 後半の中央値 |
| 後半の範囲 | 3 |
| Dを含める | TRUE |
| Cを含める | TRUE |
| 教師メール | （改行区切り） |

### 名簿

| 児童ID | 出席番号 | 氏名 | メール |

メールが本人確認の鍵になる。ここが空の児童はサイトを使えない。

### 単元マスタ

| 教科 | 単元名 | 開始No | 終了No | 色 | 学期 |

`色` は 0〜4。`学期` は 1／2／3。教師画面の設定タブがこのシートを書き換える。

### 授業マスタ

| 教科 | No | 実施日 |

**実施日を持つ理由**：「授業は済んだが未入力」と「これから」を分けるため。実施日が空または未来なら未実施として、児童の画面では操作できないセルにする。プロトタイプではこれをダミーで固定していた。

### 記録

| 教科 | 児童ID | No | 記号 | 保存時刻 | 更新者 |

**1行1評価の縦持ちにする。** 写真の一覧表に似せた横持ち（行＝児童、列＝No）にしたくなるが、**ロックが保存時刻の関数である以上、評価1つごとに時刻を持つ必要がある**。横持ちだと1セルに記号と時刻と更新者を詰め込むことになり、必ず破綻する。

年度末でも 29名 × 130時間 × 2教科 ≒ 7,500行。`getValues()` 一括読みで足りる。

教師が生の表を見たいときは、この記録から横持ちの表示用シートを別に生成する（`QUERY` 数式か、書き出し関数）。**正本は縦持ちのほう**。

### 確定

| 教科 | 児童ID | 種別 | 対象 | 値 | 確定時刻 |

`種別` は `単元` または `学期`。`対象` は単元名または学期番号。教師が採用した値だけがここに入る。仮値は入れない（仮値は毎回計算し直す）。

## 3. GAS のファイル構成

```
Code.gs        doGet・ルーティング・ロール判定
Config.gs      設定シートの読み書き（CacheService で5分キャッシュ）
Roster.gs      名簿。メール → 児童ID
Master.gs      単元マスタ・授業マスタの読み書き
Store.gs       記録の読み書き。LockService で排他
Lock.gs        ロック境界の判定
Aggregate.gs   単元評価・期末評定の計算
Export.gs      確定値の書き出し

scale.html     スケールの定義と変換（20段）
student.html   児童画面
teacher.html   教師画面
```

**`scale.html` はサーバとクライアントの両方から使う。** 記号と内部値の変換はクライアントの表示にもサーバの集計にも要る。二重に書くと必ずずれるので、1ファイルにして両方から読む。

```js
// サーバ側
eval(HtmlService.createHtmlOutputFromFile('scale').getContent().replace(/<\/?script>/g, ''));

// クライアント側（テンプレート内）
<?!= HtmlService.createHtmlOutputFromFile('scale').getContent() ?>
```

多少行儀は悪いが、スケールの定義がずれる事故のほうが高くつく。

## 4. 実装順序

各段階で動くものが残るように積む。

### Step 1 — シートを作る
5枚を手で作り、設定・名簿・単元マスタ・授業マスタを埋める。記録と確定は見出し行だけ。

### Step 2 — Scale.gs を移植して検算
`prototypes/grid-sheet.html` のスケール部分をそのまま移す。GAS エディタで往復テストを書く。

```js
function testScale(){
  for(let v=1; v<=20; v++){
    if(valueOf(symbolOf(v)) !== v) throw new Error('往復しない: ' + v);
  }
}
```

**20段への変更で最も壊れやすいのがここ。** 先に固める。

### Step 3 — 誰が開いているかを判定する（山場）
`doGet` でメールを取り、名簿と教師メールに照合して児童／教師／不明を返す。画面は「こんにちは、◯◯さん（児童）」だけでよい。

**児童アカウントで実際に開いて確認する。** ここが通らなければ以降は成立しない。

### Step 4 — 読み取りだけ通す
`Store.read(教科, 児童ID)` を作り、児童画面に実データを流す。まだ保存はしない。プロトタイプのダミーデータを差し替えるだけなので、画面はそのまま使える。

### Step 5 — 保存（ここが本番）
`Store.save(教科, 児童ID, No, 記号)`。サーバ側で必ず次を確認する。

1. **呼び出し元のメールから児童IDを引き直す。** クライアントから渡された児童IDは信用しない。他人の行を書けてしまう
2. **ロックをサーバ側で判定する。** クライアントの時計は児童が変えられる。プロトタイプはクライアント判定なので、そのまま移植しない
3. 教師なら1と2を飛ばす（貫通）。ただし `更新者` に教師のメールを記録する
4. `LockService.getScriptLock()` で囲む。29人が同時に書く

画面側は楽観的に更新する（押した瞬間に反映し、失敗したら戻す）。Chromebook から `google.script.run` は往復1〜2秒かかるので、待たせると連打される。

### Step 6 — 教師画面
一覧・集計・確定。`Aggregate.gs` の計算は `prototypes/teacher-view.html` の関数をそのまま移せる。

### Step 7 — 一斉入力
プロトタイプと同じく、既定は空欄のみ・ボタンに実人数・実行後に上書き件数を報告。サーバ側でも「上書きする」フラグがない限り既存値を書き換えない。

### Step 8 — 学期の設定と学期ごとの期末評定（未実装）

1. 単元マスタに `学期` 列を追加（すでに構造には入れてある）
2. 教師画面の設定タブに学期の列を足す。単元の並びの中で学期が変わるところに区切りを表示する
3. 検算を足す：**学期が No の順に連続していない**場合に警告（例：1学期→2学期→1学期）
4. 期末評定タブに学期の選択を足す（1学期／2学期／3学期／学年末）
5. `termFor()` を「選んだ学期の単元だけ」で計算するよう変える
6. 分布と出力も選んだ学期のものにする。出力に学期の列を足す

**切れ目を単元の属性（学期）として持たせる。** 「どの単元で区切るか」を別データにすると、単元を並べ替えたり削除したときに切れ目だけが取り残されて壊れる。

### Step 9 — 出力
確定シートへの書き込みと、通知表用の表の生成。

## 5. 落とし穴

| 落とし穴 | 対処 |
|---|---|
| デプロイを「アクセスしているユーザーとして実行」にする | 児童がシートを直接編集できるようになる。手順1のとおり「自分」にする |
| ロックをクライアントで判定する | 端末の時計を変えれば突破できる。保存時にサーバで再判定する |
| クライアントから渡された児童IDを信じる | 他人の評価を書ける。必ずメールから引き直す |
| スケールの定義をサーバとクライアントに二重に書く | 20段への変更のような修正で必ずずれる。1ファイルにする |
| 記録を横持ちにする | 保存時刻を持てず、ロックが成立しない |
| タイムゾーン未設定 | ロック境界がずれる。`appsscript.json` で `Asia/Tokyo` |
| 教師の貫通を記録しない | 「誰がいつ書き換えたか」が消える。`更新者` を必ず埋める |
