# ノート評価 — 仮決定版 v1

2026年度 3年3組（29名）。教師がノートに書いた記号を児童がサイトへ転写し、その蓄積から単元評価と期末評定を組み立てる。

**この文書が仕様の正本。** 実装で迷ったらここに戻る。ここに書いていないことは決まっていない。
経緯と取り下げた判断は `history.md`、GAS への載せ方は `implementation-plan.md`。

## 1. 何を測っているか

**「主体的に学習に取り組む態度」**。**ノートを通して見える主体性**を記録し、期末の評定に使う。

見取る側面は次のものを含む。ノートに現れたものだけを扱う。

- 粘り強さ
- 自己調整
- 他児童から学ぶ姿勢
- 積極性

到達度（知識・技能／思考・判断・表現）ではない。この一点が集約規則を決める（5節）。

## 2. 記号と内部値

**入力語彙は15記号。** 帯によって段数が違う。

```
D      C  C+      B−  B  B+  B++      A−  A  A+  A++      Z  Z+      Y  Y+
```

| 帯 | 段 | 内部値 |
|---|---|---|
| **D** | `D` | **1** |
| **C** | `C` `C+` | **2〜3** |
| B | `B−` `B` `B+` `B++` | 4〜7 |
| A | `A−` `A` `A+` `A++` | 8〜11 |
| **Z** | `Z` `Z+` | **12〜13** |
| **Y** | `Y` `Y+` | **14〜15** |

**段は見分けが要るところに寄せてある。**

- `D`（やるべきことを何もしていない）に濃淡は要らない。**1段**
- `C`（届いていない）の中の差は2つで足りる。**2段**
- `B` と `A` が最頻帯。ここをいちばん細かく見分ける。**4段ずつ**
- 上端は、そこまでの細かさを使い分けられない。**2段ずつ**

均等に刻むと、使わない段が増えるだけで判定が重くなる。

**段は表で持つ。** 掛け算（基本字 × 4）では帯ごとに段数が違う形を表せない。`LEVELS` という1本の配列が並びの正本で、変換はすべてそれを引く。

```js
const MODS_OF = { D:ONE, C:TWO, B:FULL, A:FULL, Z:TWO, Y:TWO };
//  ONE = [""]   TWO = ["","+"]   FULL = ["−","","+","++"]
```

記号は児童の意欲を引き出すための便宜的な名称で、字そのものに意味はない。**順序だけが情報を持つ。**

**保存は記号の文字列で行い、計算のときだけ値に変換する。** 逆にすると `+` と `++` の区別が消える。

### 基本字は上に足せる

さらに上位の字が要る日が来ても、**`BASES` の末尾に足し、`MODS_OF` に段数を書くだけで通る**。表の後ろに積まれるだけなので、既存の段の値は動かない。評定のしきい値も記号から引いているのでずれない。

```js
const BASES = ["D","C","B","A","Z","Y"];   // ← ここに足す
const MODS_OF = { …, "Y":MODS_TOP };       // ← 段数を書く
```

**途中に差し込んではいけない。** 既存の内部値が全部ずれて、過去の記録の意味が変わる。追加は末尾だけ。

層の境目も定数で持つ。`Y` を足せば `Y` も自動で突破層に入る。

```js
const TOP_FROM = "Z";   // これ以上は突破層（箔をかける・突破回数に数える）
const WARN_TO  = "C";   // これ以下は警告層（文字を赤にする）
```

```js
const RELEASE_FROM = "Y";   // これ以上は、教師が解放するまで児童に出さない
```

**コードのどこにも `"Z"` や `"Y"` を直接書かない。** 書いた瞬間、基本字を足したときにそこだけ取り残される。

### 上端の解放

**`Y` 以上は、教師が設定で解放するまで児童に出さない。** 天井を突き抜けた児童が出てきたときに開ける。

- 児童のプルダウンに出さない（すでに入っている記号は、値が消えないよう残す）
- **サーバも児童からの保存を断る。** 出さないのは誘導であって、権限はサーバが守る
- 教師は解放前でも置ける

設定シートの `Y解放`（既定 FALSE）。教師画面の設定タブから切り替える。

### 記号を置き換えたときの移行

`Z−` `Z` `Z+` `Z++` から `Z` `Z+` `Y` `Y+` に変えたとき、**位置で対応させたので内部値は動いていない**。

| 前 | 後 |
|---|---|
| `D−` `D` `D+` `D++` | `D` |
| `C−` `C` | `C` |
| `C+` `C++` | `C+` |
| `Z−` | `Z` |
| `Z++` | `Y+` |

`B` 以上は記号も意味も変わらない。**ただし `D` と `C` を畳んだぶん、内部値は動く**（`B−` が 9 から 4 になる、など）。記号で保存しているので記録は壊れないが、**単元評価と評定はしきい値との関係が変わる**。畳んだあとに `A下限`／`C上限` を確かめること（既定は `A+` と `C+`）。

`migrateSymbols()` が記録と確定の記号を置き換える。**2回実行しても、置換先の記号は表に無いので当たらない。**

## 3. 教師用アンカー

**児童には見せない。教師の判定を時点間で安定させるためだけに使う。**

規準がないと、同じ記号が時点間で同じ水準を指す保証がない（評価者内ドリフト）。単元後半ほど期待水準は上がるため、ドリフトは児童の伸びを打ち消す方向に働く。70時間分を単元評価に集約する以上、これは無視できない。

**基本字が帯を決める。**

| 字 | 規準 |
|---|---|
| `Z` | **十二分。** 想定以上。文句のつけようがない |
| `A` | **十分。** この授業にこれだけできていればいい 〜 かなり深く主体的に取り組んでいる |
| `B` | **最低限。** やる気は見られないが、最低限の体裁は整えている |
| `C` | **明確に不十分。** やっていないところがある |
| `D` | **未着手・態度が悪い** |

**`−` / 無印 / `+` / `++` は、その帯の中のどこにいるかを表す。** `A` の規準が「これだけできていればいい」から「かなり深く」までの幅として書かれているとおり、字は帯であって点ではない。`A−` は帯の下端（十分のぎりぎり）、`A++` は帯の上端（次の帯に届きそう）。

したがって次が同じことを指す。

- 「もう少しで `Z`」＝ `A++`
- 「十分だが上乗せはない」＝ `A−` 〜 `A`

**この帯内の刻み方は未確定。** 4段を実際に区別して付けられるかは運用で確かめる。区別できない段が出たら、その帯だけ段を減らすのではなく、記録に現れた分布を見て判断する（段を減らすと過去の値の意味が変わるため、安易には動かせない）。

### アンカーと評定のずれ

**`A`（十分）は評定では B に落ちる。** 記号のアンカーは授業1時間での到達を測っており、評定は学期を通した水準を測っている。日々の記号を実態より上へ振ってあること（6節）と合わせると、こうなる。

| 記号のアンカー | 評定 |
|---|---|
| `Z`（十二分） | A |
| `A+` / `A++`（十分の上寄り） | A |
| `A−` / `A`（十分の下寄り） | **B** |
| `B` 系（最低限） | B |
| `C` 系（明確に不十分） | C |
| `D` 系（未着手） | C |

**懸念：`B`（最低限・やる気は見られない）から `A`（十分）までが、評定 B の1つの帯に入る。** 目安では評定 B が7割なので、児童の7割がこの幅の中に収まることになる。幅が広いぶん、B 帯の中の `−`〜`++` が実質的に序列を決める。運用して分布が `B+`〜`A` に固まるようなら、`B` と `A` のあいだに1段要る。

（以前から挙がっている裏返しの懸念もそのまま残る：`C` を警告に使っているため、「取り組んだが届かなかった」を警告なしに表す段が `B` 帯しかない。）

## 4. スケールに乗らない記号

| 記号 | 意味 | 誰の都合か |
|---|---|---|
| `休` | 児童がいなかった | 児童側の欠測 |
| `/` | その授業を評価に含めない（行事・テスト・予備時間など） | 授業側の都合 |

どちらも集計から外すが、**理由が違うので分けて数える**。まとめて「欠測」にすると、「休みが多い児童」と「評価しない授業が多い単元」が区別できなくなる。

**`/` は教師だけが設定する。** 授業側の都合で決まるものなので児童のプルダウンには出さない（すでに入っているセルでは、値が消えないよう選択肢に残す）。授業単位で決まることが多いので、教師画面の**一斉入力で全員に入れる**のが典型的な使い方。

## 5. 集約の規則

- **平均は取らない。** 順序尺度なので D→C の幅と `A+`→`Z−` の幅が等しい保証がない。
- 既定は**後半1/3の中央値**。単元は積み上げ構造で、態度も単元前半は様子見になりやすい。教師が変更できる。
- `休` と `/` は分母からも外す。入力数は「入力 12/16、休 2、/ 1」のように分けて出す。

### 中央値が段の間に落ちたとき

偶数個のときは2段の中間に落ちるが、順序尺度なので平均は取れない。**下側を採る**（水増ししない）。

以前は `++` を `+` と同値にしていたため「`+` と次の文字の中間」を `++` で表す特別扱いを置いていた。`++` を独立した段にしたことで、この特別扱いは不要になった。

### D と 休

| 記号 | 意味 | 集計 |
|---|---|---|
| `D` 系 | やるべきことをしていない | **含める**（態度の観測） |
| `C` 系 | 到達していない | 含める |
| `休` | 児童がいなかった | **常に除外** |
| `/` | その授業を評価に含めない | **常に除外** |

測っているのが態度なら、**D「やるべきことを何もしていない」は欠測ではなく、態度についての最も重い観測値**。除外すると評価対象そのものを捨てることになる。D を除外する設定も残してあるが、既定は「含める」。

### 単元評価をいつ児童に見せるか

**単元評価は、教師が設定画面で「単元の評価をする」を押すまで児童の画面に出ない。**

理由は動機づけではなく**不正防止**。過去に、面白がって事実と異なる記号を書いた児童がいた。単元評価が転写と同時に動くと、「記号を上げると数字が上がる」がその場で確かめられてしまい、遊びとして成立する。**押すまで数字が動かなければ、その場のフィードバックが存在しない。**

| 押す前 | 押した後 |
|---|---|
| 値は `—`。タグは「とちゅう」／「せんせいが かくにんちゅう」 | 値が出る。タグは「せんせいの ひょうか」 |
| 入力数・`休`・`/` の回数は出る（事実の記録） | 同じ |
| 「いちばん」「Z以上の回数」は**出さない** | 出る |

「いちばん」と「突破の回数」も単元の到達度の要約なので、同じ旗で隠す。見えていると同じ遊びが成立する。**入力数と `休`・`/` の回数は事実の記録なので常に出す**（自分の転写がどこまで進んだかは分からないと困る）。

**押した後に出るのは、教師が採用した値。** 児童画面での再計算ではない。再計算のままだと、押した後も転写を書き換えるたびに数字が動き、旗の意味がなくなる。

旗は単元マスタが持つ（`rated`）。教師画面には押す前でも仮値が出るが、「まだ児童に見せていない」と表示される。もう一度押せば下げられる。

授業ごとの記号そのもの（表のセル・折れ線）は、児童が入力した値をそのまま返しているだけなので隠さない。

## 6. 期末評定への写像

**日々つける記号は、児童のやる気を引き出すために実態より上へ振ってある。** したがって記号と評定は一致しない。実際に A 評定になるのは `A+` 以上。

| 記号 | 評定 |
|---|---|
| `A+` `A++` `Z` `Z+` `Y` `Y+` | **A** |
| `B−` `B` `B+` `B++` `A−` `A` | **B** |
| `D` `C` `C+` | **C** |

記号の `A` や `A−` は評定では **B** に落ちる。ここを取り違えると評定が一段甘くなる。

**B と C の切れ目は `C+` 以下が C。** 上振れは上位帯だけの現象で、下位帯は実態どおり付けている。C 評定は「ノート評価で C・D が続き、代表値が C 帯に入った児童」だけという運用と一致する。

しきい値は教師画面で動かせる。

### 分布の目安

| 評定 | 目安 |
|---|---|
| A | 3割ほど |
| B | 7割ほど |
| C | いるかいないか（0〜1名） |

教師画面の「期末評定」タブに実際の分布を出す。目安から外れた数字は赤で出るので、しきい値を動かして合わせられる。**この目安は担任の実感によるもので、集団が変われば動く。**

代表値は次から選ぶ。既定は**後半の中央値**。

| | |
|---|---|
| 後半の中央値（既定） | 単元終盤の実力 |
| 全体の中央値 | 単元通しての安定水準 |
| 後半の平均値／平均値 | — |
| **内側の平均値** | 最大と最小を1つずつ落としてから平均する |
| 最頻値／最高 | — |

**平均は順序尺度では本来取れない**（`D`→`C` の幅と `A+`→`A++` の幅が等しい保証がない）。それでも使うなら、1回の突出や1回の落ち込みに動かされにくい**内側の平均値**のほうが実態に近い。3つ未満のときは落とさない。

複数単元のまとめ方も同じ選択肢から選ぶ。

### 学期

単元は `学期`（1／2／3）を属性として持つ。期末評定は**選んだ学期の単元だけ**で計算する（学年末を選べば全学期）。採用した評定は `教科 × 学期` ごとに分けて持つ。

切れ目を「どの単元で区切るか」という別データにすると、単元を並べ替えたり削除したときに切れ目だけが取り残されて壊れる。**学期が単元自身に付いていれば整合が崩れない。**

設定画面で次を検算する。

- 学期が No の順に戻っていないか（1学期 → 2学期 → 1学期）
- 同じ学期の単元が No の上で連続しているか

## 7. 教科

教科は教師が足せる。**足した教科は最初、児童の画面に出ない。** 単元と授業の区切りを入れ終わるまで児童に見せると、色も単元名も付かない空の表を転写させることになる。

| 状態 | 児童 | 教師 |
|---|---|---|
| 公開 | タブに出る | タブに出る |
| 非公開 | **出ない** | 灰色の斜体でタブに出る |

公開の切り替えは教師表示のタブ横のボタン1つ。切り替えた教科はその場で児童のタブに出る。

**非公開はサーバ側でも弾く。** タブを出さないのは操作の誘導であって権限の実装ではない。

現在：算数・国語（公開）／体育・社会（非公開。単元は仮置き）。

## 8. ロック

**ロックは状態として持たず、保存時刻から毎回引く。**

```
直近の境界 = 今日の定時（すでに過ぎていれば今日、まだなら昨日）
ロック済み ⇔ その評価の保存時刻 < 直近の境界
```

日次トリガでフラグを書き込む方式にしない理由：

- トリガが落ちた日に全員のロックが飛ぶ。時刻の関数なら落ちようがない
- 書き戻す状態がないので、シートとフラグの不整合が起きない
- 過去の任意時点のロック状態を後から再現できる

**未入力のセルはロックしない。** 保存時刻がないので、そもそも判定の対象にならない。休んだ児童も、転写を忘れた児童も、後日そのまま入力できる。

**ロック後に直す必要が出たときは、教師が貫通して直す。** 児童に解除の手段は持たせない。持たせると「一度出したら直せない」という前提が崩れ、転写がやり直し前提の作業になる。

**教師アカウントはロックを貫通する。** 貫通して書き換えたセルには印が残る。判定は Google アカウントで行う。**定時は 16:00。** 教師画面で変更できる。

16:00 に置いた理由は、**境界が誰も使っていない時間に落ちること**。3年生はその時刻には下校している。境界が転写中の時間帯に落ちると、15:59 に入れた児童は1分で確定し、16:01 に入れた児童は翌日まで直せる、という差がその場で出る。同じ日に転写した児童が同じ扱いになるよう、境界は活動の外に置く。

**児童の画面にロックの説明は出さない。** 「まだ直せる」は斜め縞が示している。文章で足すと、毎回読まされる情報が1つ増える。

### 授業の実施日は持たない

以前は授業マスタに実施日を持ち、「済んだが未入力」と「これから」を分けていた。**やめた。** 埋める手間に見合わず、埋め忘れると児童の画面が1つも入力できない状態で黙って止まる。

いまは**時数の範囲すべてがいつでも入力できる**。まだ習っていない授業に児童が書き込むことは起こりうるが、ノートを見ながら転写する作業なので、書くものが無ければそもそも書かない。

時数は教師画面の設定タブで後から変えられる。減らしても記録は消えない（範囲の外に出るだけ）。

### 待たせるときは画面ごと止める

**終わるまで次の操作をさせてはいけないものは、画面を物理的に覆う。** 覆いの下には触れないので、待っているあいだの連打が起きない。

| 覆う | 覆わない |
|---|---|
| 読み込み・教科の切り替え | **1マスの保存** |
| 教師の採用・一斉入力・設定の保存・書き出し | |

**1マスの保存では覆わない。** 押した瞬間に反映するのが要点なので、そこで画面を止めると転写がかえって遅くなる。代わりに**そのマスだけ**往復のあいだ受け付けない。連続して別のマスを押すのは妨げない。

### 開室時間

**児童がサイトを使えるのは 8:00 から ロック時刻（16:00）まで。** それ以外の時間は表を出さず、「きろくを こうしんして います／あさ 8:00 から つかえます」とだけ出す。

**終わりの時刻を別に持たず、ロック時刻をそのまま使う。** 別々の値にすると「閉まっているのにまだ直せる」「開いているのにもう確定している」というずれが生まれ、それを人手で守り続けることになる。同じ値を見れば、**閉室と確定が必ず同じ瞬間に起きる**。

| 時刻 | 児童 | 教師 |
|---|---|---|
| 8:00〜15:50 | 表が出る | 出る |
| 15:50〜16:00 | 表＋「あと ◯ふんで、きょうは おしまいです」 | 予告なし |
| 16:00〜翌8:00 | **閉室の画面だけ** | 出る（ロックの貫通と同じ） |

開いたまま16:00をまたいだ画面は、60秒ごとの確認で自動的に閉室へ切り替わる。**確認は時刻だけを見る軽い入口で行い、記録は読み直さない**（毎分ぜんぶ読み直すと、29台ぶんの空読みが毎分走る）。切り替えの10分前から予告を出すのは、**画面が突然消えたと思わせないため**。16:00 は児童が下校している時刻なので、この予告が出る場面はまれ。

**サーバ側でも弾く。** 画面を閉じるのは誘導であって権限ではない。読み取りも保存も、時間外の児童の要求を断る。

## 9. 全員への一斉入力

教師画面から、単元内の1授業を選んで29名全員に同じ値を入れられる。学級閉鎖・行事・出張など、全員が同じになる日のための機能。

- 既定の対象は**空欄の児童だけ**。上書きは明示的に選んだときだけ行う
- ボタンには実際に入る人数が出る（`23名に入れる`）
- 実行後に「うち上書き ◯」を報告する

上書きは取り消せないので、既定を安全側に置いてある。

## 10. 色と材質

情報の通り道を3つに分け、混ぜない。

| 通り道 | 使うもの |
|---|---|
| 評価の高さ | プルダウンの地色と材質 |
| セルの状態 | 半透明の斜め縞（色は使わない） |
| 単元 | プルダウン上端 3px の色（20色） |

**評価の色**：`A` 系と突破層にだけ色を置く。`B` 系は無色、警告層（`D`/`C`）は塗らずに文字だけ警告色。

スケール外の2記号は**同じ地色**にする（集計での扱いが同じだから）。違いは中身で示す。`休` は文字で書き、`/` は**文字を出さず、欄を斜めに1本の線が横切る**。線そのものが「この欄は無い」を示す。

閉じた `select` は選択中の文字をそのまま出すので、`/` のときは文字色を透明にしている。**セルの状態ごとの文字色は `/` に当てない**（`:not(.is-skip)` で外す）。当てると詳細度で透明が上書きされ、線の上に `/` の字が重なって出る。**状態の色は「出す文字がある記号」にだけ当てる。**

開いたリストの中では `/` の文字が出る。これは選ぶための手がかりで、教師しか開かない。

**装飾は基本字ごとに1つ。段（`−` / 無 / `+` / `++`）では変えない。**

| 基本字 | 見た目 |
|---|---|
| `Z` 系（`Z` `Z+`） | 金の箔。粒・斜めの走査光・地のグラデーションを合成し、走査光を流す |
| `Y` 系（`Y` `Y+`） | 宇宙。ほぼ黒の地に星を散らし、紫と青の星雲をゆっくり流す |

段ごとに装飾を変える案は一度作って戻した。段が増えるたびに新しい装飾を考えることになり、**基本字を足せる設計と噛み合わない**。字ごとに1つなら、字を足すときに1つ決めれば済む。

```js
const BASE_LOOK = { "Z":"foil-gold", "Y":"foil-cosmic" };   // 未登録の字は金の箔
```

**単元評価の見せ方**：単元カードの値は、プルダウンと**同じ縦横比（約3:1）の枠**に入れ、幅だけ大きくする。塗りは**1段階上の基本字の材質**（`A` なら `Z` の金の箔、`Z` なら `Y` の宇宙）。単元で高い値を取るのは1時間で取るより難しいので、同じ記号でも授業のセルより上に見せる。文字色だけを変える案は採らなかった（上位の材質は背景であって文字色では表現できない）。

**ただし警告帯（`D`・`C`）は上げない。** 上げると「単元で C だった」という警告が消える。上げる操作は達成の方向にだけ意味を持つ。

枠の上端に単元色は置かない。単元はカードそのものが表しているので、カード上端の色で足りる。

**単元の色**：20色を巡回する。色相を 126° ずつ飛ばしてあるので、**連番の単元が隣り合っても色が近づかない**（20 と 126 は互いに素）。明度は色相ごとに補正して、黄が浮いて青が沈むのを抑えてある。番号は単元マスタの `c` が持ち、**両画面が同じ番号を見る**（教師が設定タブで変えた色がそのまま児童の表に出る）。

**セルの地は常に紙。** 単元も状態もプルダウンの上に載せることで、セルの地色というチャネルを空けたままにしてある。

**セルの状態**：色を使わず、半透明の斜め縞を「まだ変えられる」の印にする。縞は透明度でつくってあるので、評価の色（青・金）の上でも透けて見える。

| 状態 | 見え方 |
|---|---|
| まだ変えられる（未記入・入力済みとも） | プルダウンに斜めの薄い縞。未記入は左右下の枠が破線 |
| 確定（ロック済み） | 紙のまま。印は置かない |
| これから | グレー・操作不可 |
| 教師が確定済みを開いている | 枠が破線 |
| 教師が貫通して書き換えた | セル左端に細い線が残る |

## 11. 画面

### 児童

もとの一覧表と同じ形。No.1〜70 の各セルがプルダウン。上部は「教科タブ → 名前と残数 → 表」だけで、説明は置かない。

**開いたときは、いまやるところが中央に来る。** 先頭から見せると毎回スクロールして自分の位置を探すことになる。未入力の最初のセル、なければ最後に入力したセルへ寄せる。

下に単元評価と、記号の推移の折れ線。**単元評価は教師が押すまで出ない**（5節）。

**単元評価は学期ごとに畳める。既定はいまの学期だけ開く。** 4〜7月は1学期、8〜12月は2学期、1〜3月は3学期。70時間ぶんのカードを全部開くと、いま関係のあるものが埋もれる。

読み込み中は「よみこんで います…」を出す。何も出ない時間を作らない。折れ線は動機づけ装置として置いているが、**3年生がこれを「自分の伸び」として読めるかは未検証**。読めなければ「前回より上がった / 同じ」の一言に差し替える。

**最頻値（`A`・`B+`）を強調するような誘導はしない。** これは選択ではなく転写なので、誘導は誤写を増やすだけ。

### 教師

タブ3枚。

1. **単元ごと** — 29名 × 単元の一覧、仮値と指標（入力数／休／対象外／全体中央値／最高／突破回数／C回数／D回数）、採用、一斉入力、TSV 出力
2. **期末評定** — しきい値、分布と目安、児童ごとの評定、採用
3. **設定** — いまの状態（`diagnose`）、しきい値と時刻、教科の追加・時数・公開、単元の範囲・色・学期の編集と検算、`Y` の解放、スプレッドシートへのリンク

**「単元の評価をする」は単元ごとタブにある。**

画面の中の相対リンクは iframe の中で解決されて別の場所へ飛ぶ。**サーバが返した絶対 URL を使い、`target="_top"` で親ごと移る。**

児童画面の教師表示からタブ横のリンクで移る。**リンクを出さないのは誘導であって権限ではないので、飛んだ先でも役割をメールから判定し直す。**

## 12. 児童用端末での重さ

端末は CZ1104FM2A（Chromebook・MediaTek Kompanio 500）。**CPU を6倍遅くして実測した**（この機の1コアは開発機のおよそ 1/4〜1/6）。

| | 実測（6倍スロットル） |
|---|---|
| ページの表示まで | 1.2 秒 |
| **1タップ（記号を1つ入れる）** | **4 ms** |
| **表の組み立て（教科の切り替え）** | **9 ms**（前は 186 ms） |
| アニメーション中のフレーム | 16.7 ms（60fps・落ちない） |
| JS ヒープ | 9.5 MB |
| ファイル | 46 KB（gzip 15 KB） |

DOM は 514 要素、`option` は 70 個（前は 1,911 要素・1,051 個）。**重さのほぼ全部が `option` の数だったので、そこを削った。**

### 表を作り直さない

かつては1タップごとに表全体（70個の `select` × 22個の `option`）を作り直していた。実測で **1タップ 148ms**。内訳を測ると 135ms が DOM の組み立てで、文字列をつくる JS は 2ms だった。**遅いのは JS ではなく、`option` を 1,500 個作り直すこと。**

いま1タップで触るのは、そのセルのクラスと選択値だけ（`applyCellState`）。表を作り直すのは**教科と役割が変わったときだけ**。148ms → 4ms。

**新しいセル状態や材質を足すときは `applyCellState` に足す。** `renderGrid` の側に書くと、タップのたびに反映されない状態ができる。

### 選択肢は開くまで作らない

表を作り直す回数を減らしても、**作り直す1回そのものが重い**。70個の `select` に15段ぶんの `option` を入れると 1,051 個になり、6倍スロットルで **186 ms** かかっていた。

いま最初に入れる `option` は**いま入っている記号1つだけ**（空なら `‥`）。児童がそのマスを触った瞬間に、その `select` だけ15段を作る（`fillOptions`）。開いていないマスの選択肢は最後まで作らない。

- 聞き役は表に1つだけ置く（イベント委譲）。70個に付けると、付ける作業だけで表の組み立てと同じ重さになる
- `pointerdown` / `focusin` / `keydown` の3つで拾う。**マウスだけで拾うとキーボードで開いたときに空になる**
- 一度作った `select` には印を付けて二度作らない（`dataset.full`）

186 ms → **9 ms**。要素数 1,911 → 514。

### 記録はサーバ側でキャッシュする

29名が同じ時間に開くので、**1人目だけがシートを読み、残りはキャッシュから返す**。記録シートは7,500行あり、1回の読み取りが往復のほとんどを占める。

- 読むときは教科ぶん全部を1回で読み、**児童ごとに分けて 30分**入れる（`CacheService.putAll`）
- 書いたら**その児童の分だけ**捨てる。他の28名のキャッシュは生きたまま
- 教師の一斉入力・採用のあとは教科ごと捨てる

キャッシュが無くても動く（その場でシートを読む）。**速さのための仕組みであって、正しさはシートが持っている。**

### フォントで画面を止めない

`IBM Plex Sans JP` は日本語のウェブフォントで、校内から `fonts.googleapis.com` が遅い・届かないことがある。`<link rel="stylesheet">` を直接置くと、**その間ずっと画面が白いまま**になる。

| フォントの状況 | 最初の描画まで（直す前） | 直した後 |
|---|---|---|
| すぐ返る | 0.2 秒 | 0.2 秒 |
| 3秒かかる | 3.3 秒 | 0.2 秒 |
| 届かない（校内で遮断） | **9.3 秒** | 0.2〜1.1 秒 |

`media="print"` で読み込んで、届いてから `all` に変えている。届かなければ端末のフォント（ChromeOS なら Noto Sans CJK）で出る。**日本語は読めるので、フォントは無くても困らない。**

## 13. ファイルの構成

スケールの定義と色トークンと単元マスタは**1箇所にしか置かない**。両画面がそれを読む。

```
build.py                      src/ を組み立てて prototypes/*.html を書き出す
prototypes/src/
  scale.js       ← 正本   20段の定義・変換・層判定・休と/・中央値
  tokens.css     ← 正本   色トークン（@dark{} は build.py が2つに展開する）
  units.js       ← 正本   教科と単元のマスタ（open / c / term / rated）
  material.css   ← 正本   材質（金の箔・宇宙）
  grid-sheet.html         児童画面の本体
  teacher-view.html       教師画面の本体
prototypes/
  grid-sheet.html         生成物。直接編集しない
  teacher-view.html       生成物。直接編集しない
```

```
python3 build.py           生成する
python3 build.py --check   生成物が src と一致するか調べる
```

**この構成にした理由**：以前はスケール定義が2つの HTML に別々に書かれていて、実装がすでに食い違っていた（`valueOf` のスケール外ガード、`isTopSym`）。単元の色も、教師画面は `u.c` を見るのに児童画面は並び順から出していたので、**教師が選んだ色が児童に届いていなかった**。

出力が単一ファイルなのは変えていない。アーティファクトへの公開手順も、校務 PC での開き方も変わらない。GAS では `scale.html` をサーバとクライアントの両方から読む形になるので、いま同じ形にしてある。
